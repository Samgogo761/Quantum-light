# 数据地图与复现说明

## 1. 目录与体积

| 路径 | 内容 | 体积 |
|---|---|---:|
| `results/bias_v2/runs/` | 96 条 TDSE 的 config、provenance、summary | 约 2 MB |
| `results/bias_v2/readouts/` | 176 项共同/控制读出的 summary、spectrum.csv | 约 220 MB |
| `results/bias_v2/reports/v3_r2_20261106/` | 最终统计与积分审计 CSV/JSON | 约 1 MB |
| `results/bias_v3_audit/reallocation_20261106/` | 误差表、S4/尾部/相位证据、判定修订 | 约 2 MB |
| `data/raw/bias_v2/` | 96 个 `state_100fs.npz`（原始波函数） | 519 MB |
| `configs/continuation_v2/` | 派生的运行配置 | 约 1.3 MB |
| `logs/` | 批次与编排日志 | 约 0.6 MB |

**核心交接包不含 96 个 NPZ**（519 MB），原因与校验方式见第 6 节。所有 summary、config、谱 CSV 均在包内。

## 2. run_id 命名规则

| 前缀 | 含义 | 示例 |
|---|---|---|
| `bias_p1_` | 早期单偏压/主状态 | `bias_p1_F0.000_I1_phi000_r02` |
| `bias_p2_` | 第二批四相位/控制 | `bias_p2_F1.000_I4_phi090_r02` |
| `bias_v2_probe_` | 8μ/32μ 高风险探针及控制 | `bias_v2_probe_F1_I32_phi000_dt005_r01` |
| `bias_v2_lib_` | 生产库节点 | `bias_v2_lib_F0_I20_phi180_r01` |
| `bias_v2_mid_` | 插值中点（6μ、10μ） | `bias_v2_mid_F1_I6_phi270_r01` |
| `bias_v2_s4_` | S4 代表点 dx/dt 控制 | `bias_v2_s4_F0_I8_phi000_dx048_r01` |
| `bias_v2_ph8_` | 4→8 相位验证 | `bias_v2_ph8_F1_I32_phi045_r01` |
| `bias_p1_dc_` | 无光 DC-only 背景 | `bias_p1_dc_F1.000_r02` |

命名中的 `F` 是偏压（V/nm）、`I` 是 `I/μ` 倍数、`phi` 是 CEP 角度、`r01/r02` 是修订号。
**不要仅凭文件名推断参数**，以 `config.json` 为准。

## 3. 一条 run 的文件关系

```text
configs/continuation_v2/<run_id>.json          派生配置（写入时冻结）
results/bias_v2/runs/<run_id>/config.json      同一配置的副本
results/bias_v2/runs/<run_id>/provenance.json  源码哈希、父配置哈希、Git commit
results/bias_v2/runs/<run_id>/summary.json     传播结果、execution_status
data/raw/bias_v2/<run_id>/state_100fs.npz      100 fs 保存态（核心包不含）
results/bias_v2/readouts/<readout_id>/summary.json   读出结果
results/bias_v2/readouts/<readout_id>/spectrum.csv   E_corr / K_inf / S(E)
```

`readout_id` 由 `run_id + 保存时间 + η + ΔE + mask + 能量范围` 唯一决定，例如
`ro2_bias_v2_lib_F0_I20_phi000_r01_t100_eta0p05_dE0p0125_m2-4`。不同 η/ΔE/mask 的谱**不可混用**。

## 4. 账本字段

`results/bias_v2/compute_ledger_v2.csv`：

| 字段 | 含义 |
|---|---|
| `event_id` | `tdse:<run_id>`、`readout:<readout_id>`、`attempt:<run_id>:<原因>` |
| `kind` | `tdse`、`readout`、`tdse_attempt` |
| `phase` | 历史阶段标签（R1/R2/R3），**不能**用它单独筛 S3 |
| `run_id` | 对应 run；readout 行也写原 run_id |
| `counted_seconds` | 计入预算的秒数 |
| `status` | `PASS`、`failed`、`INTERRUPTED_POWER_LOSS_ESTIMATED` |

当前 273 事件 = 96 TDSE + 176 读出 + 1 中断 attempt。中断 attempt 的 0.5 h 是暂估预留。

## 6. 原始 NPZ 的缺失与校验

- 96 个 `state_100fs.npz` 共 519 MB，未放入核心包，也未上传 GitHub（避免超过仓库与单文件限制）。
- 校验清单：`07_关键结果与误差审计/raw_state_manifest.csv`（路径、字节数、SHA256）。
- 取回方式：从原工作区 `QL-TIP-1D/data/raw/bias_v2/` 复制，或由负责人提供移动硬盘副本。
- 缺 NPZ 不影响：读取 summary、重画响应曲线、复核统计与误差；但**不能**重算谱或改变读出参数。

## 7. 复现边界

- 归档 `check` 只校验已登记原件与包链接，不覆盖所有 NPZ 的内容重哈希。
- `_readout_ok()` 只检查 summary 协议值与字段存在，不做内容重哈希。
- `source_freeze` 校验冻结源码版本，不覆盖运行中磁盘漂移。
- 20μ 批次曾跨越一次源码修订，其 provenance 按进程加载版本记录，不能声称每条都是同一源码版本。
