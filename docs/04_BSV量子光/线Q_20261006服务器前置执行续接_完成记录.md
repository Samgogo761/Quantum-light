### 隔离 CUDA 环境

- Python：3.13.14。
- PyTorch：2.11.0+cu128；CUDA runtime：12.8。
- GPU：NVIDIA GeForce RTX 5060 Ti，1 张；驱动 591.86；显存总量约 16311 MB。
- `torch.cuda.is_available()`：`true`。

### 复数组对照

在 48 个频率（low 8、H2 附近 16、mid 16、high 8）、192 个 photon columns、64 个 dark columns、共 256 列、16 步的短测上：

- CPU 列块拆分：`ok=true`；泵浦窗口的 `b/bdag/A/final_I/ΔU/V` 拆分误差均为 0。
- CUDA 后端：`ran=true, ok=true`。
- 对照覆盖 start/pump 两个窗口，以及 driven−undriven 和 undriven；逐元素比较 `b`、`bdag`、`A`、最终电流、`ΔU`、`V`，`atol=1e-10, rtol=1e-8` 全部通过。
- pump 窗口的最大绝对误差量级：`bdag≈4.66e-16`、`A≈9.60e-16`、`final_I≈2.79e-14`、`ΔU≈7.74e-18`、`V≈7.88e-18`。
- 这证明 CUDA 后端与 CPU midpoint/feedback wiring 等价；不证明 BZ 收敛、`n,m` 资格或磁畴物理。

### 列块吞吐短测

复用同一 256 列 fixture，在 pump 代数窗口、16 步、每个块重复两次：

| block size | blocks | 覆盖列数 | 最快总 wall | peak allocated | peak reserved |
|---:|---:|---:|---:|---:|---:|
| 64 | 4 | 256 | 0.3105 s | 30,955,008 B | 106,954,752 B |
| 128 | 2 | 256 | 0.1678 s | 52,208,640 B | 106,954,752 B |
| 256 | 1 | 256 | 0.0894 s | 94,712,320 B | 106,954,752 B |

256 列是当前短测中最快的候选，但不能仅凭这一档决定服务器最终块大小。完整任务仍需在目标分区测显存并发、实际吞吐、写盘和调度开销。

### 成本更新

- 当前 CPU 短测完整 wall 外推：单条传播约 `54.93 h`，有泵 + 无泵约 `109.87 h`。
- 以 GPU 256 列短测的两次观测做线性外推：单条约 `4.39–4.96 h`，有泵 + 无泵约 `8.78–9.92 h`。
- GPU 数字只是 16 步/256 列短测外推，不是完整 9216 步作业的实测墙时；尚未包含完整预处理、9216 步顶点缓存、装配、写盘、调度和资源余量。
- 完整规模仍是 76496 photon columns + 1976 dark columns = 78472 columns、9216 steps；按 block size 256 约 307 个列块。

## 结论与投放边界

当前可以确认：

1. 隔离 CUDA 实现已经通过覆盖 H2、高频、暗列、弱/明显泵浦窗口的 CPU/GPU 复数组对照。
2. 可以继续做**小规模 CUDA 试算**、目标服务器上的分块吞吐/显存短测，以及已验证列块 worker 的试运行。
3. 当前还不能把完整 `+N` 的 9216 步、78472 列作业当作已经批准的生产投放。必须先由服务器侧补齐：目标分区的实际块大小/显存并发、完整路径预处理与写盘成本、分块启动与合并脚本、以及覆盖两条传播和余量的 wall-time 授权。
4. `-N`、真实 BZ 的 `n,m`、磁畴差和物理结论继续阻塞；本轮不重新打开 D、初态、Hamiltonian、P1、packet 或物理路线。
