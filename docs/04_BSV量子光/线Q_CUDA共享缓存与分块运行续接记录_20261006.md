`46.6148 s`。因此旧记录中的 `42.85 s` 不再采用。

按 `78472/1024` 列块和 `9216/2176` 步数做的只是线性参考外推，得到
benchmark 传播口径下约 3.95 h（driven+undriven）；按最新直接 worker 的
两条传播 wall 约 3.97 h，按完整 worker wrapper 约 4.20 h。它们都只是
本机连续小列集外推，不是生产作业保证，也没有把完整 9216 步顶点准备、
全量 cache 写盘、服务器 I/O、调度等待和安全余量当成已经实测。旧的

## 可复制命令

以下命令在仓库根目录执行。CUDA 命令使用本机已验证的 Python 3.13
环境，并显式加入 `.venv_q8_cuda` 的 site-packages：

```powershell
$env:PYTHONPATH=(Resolve-Path -LiteralPath '.venv_q8_cuda\Lib\site-packages').Path
$PY='C:\Users\26507\.workbuddy\binaries\python\versions\3.13.12\python.exe'
```

Fixture prepare：

```powershell
& $PY tools\b0_small_model\q8_m0_gamma12_runner_20261006.py prepare `
  --run-root results\q_line\p1_h2_finite_kcv_gamma12_runner_fixture_20261006 `
  --fixture results\q_line\p1_h2_finite_kcv_gamma12_backend_cuda_resume_20261006\backend_fixture.npz
```

连续小集 prepare：

```powershell
& $PY tools\b0_small_model\q8_m0_gamma12_runner_20261006.py prepare `
  --run-root results\q_line\p1_h2_finite_kcv_gamma12_runner_continuous_1024_20261006 `
  --model --steps 2176 --ntpc 1024 --max-columns 1024 `
  --n-dark 64 --neel 1 --a-star 0.8 --n-panel 96
```

正式 worker 的模板（只显示，不应在本单自动投完整长算）：

```powershell
& $PY tools\b0_small_model\q8_m0_gamma12_runner_20261006.py worker `
  --run-root <RUN_ROOT> --manifest <RUN_ROOT>\manifest.json `
  --backend cuda --window continuous `
  --block-id <BLOCK_ID> --column-start <START> --column-stop <STOP>
```

正式 merge 模板：

```powershell
& $PY tools\b0_small_model\q8_m0_gamma12_runner_20261006.py merge `
  --run-root <RUN_ROOT> --manifest <RUN_ROOT>\manifest.json `
  --window continuous --require-all `
  --output <RUN_ROOT>\merged_continuous.npz
```

恢复原则：只重跑缺失或 hash/元数据不通过的 block；不覆盖已经
`complete=true` 且 hash 通过的 block；不把 `column_start/stop` 当成
物理 k 分块，每个入射列仍带着完整的 2304 电子坐标和共同反馈。
