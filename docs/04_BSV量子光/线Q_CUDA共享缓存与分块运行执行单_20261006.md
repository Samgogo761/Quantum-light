## 2. 不变的物理范围

只做 +N 的工程衔接。M0、P1、初态、D、gamma、规范、探测波包、输入频率求积及权重不改；complex128/float64，不使用混合精度或新增耗散。保留有泵与无泵两次传播和原相减定义。

Gamma12：2304 电子坐标；76496 光子列 + 1976 暗列 = 78472 列。每个入射列内部都含全部 k 的共同反馈。可按独立入射列分块，不可拆 k 成互不反馈的材料实验。

暗基和其他共同数据只准备一次；暗列分块传播后全局恰好一次，不能给每个光子块附加整套暗真空。禁止依据零泵浦“暗”删除自由度。

## 3. A：共享缓存与唯一列清单

实现 prepare，输出带版本和哈希的 manifest：
- 物理参数、N、Gamma12 点/权重、电子标签及顺序、D/gamma、步长、时刻范围；
- 光子频率、原始全局频率索引、dnu、端口、偏振和稳定 column_id；
- 暗基固定列标签、顺序和基底哈希；
- detector/packet、U0 构造约定及所需数据；
- 有泵/无泵中点顶点缓存及哈希；
- 代码版本/哈希、运行环境。

只在 prepare 构造一次共同电子谱、暗基和选定时段的两套电子背景。初始光子列可以按块装配，不要求先分配全部 5.4 GiB 状态。worker 不得重新做 BZ/暗基/电子背景传播。

缓存一次解压到内存，或用适合切片的 NPY/memmap；不要在步进或逐块计时中反复索引压缩 NpzFile。是否上传全部顶点或分时间片上传可由执行者按内存决定，需记账。

sqrt(dnu) 仅在现有归一入口乘一次；不得因列数变少重新归一，也不得按块重算光子模式归一化。短测仅选取完整求积中的列，不能另造一套低密度求积。

## 4. B：worker、落盘与 merge

worker 接收 manifest 和明确列 ID/范围，返回同列顺序的：
- U0，或足以按同一 manifest 无歧义恢复它的引用；
- 两条传播的原始收缩行以及相减后的 delta_U、V；
- 列 ID、物理参数/缓存/代码哈希、步数、时间范围、后端和精度；
- 准备、上传、循环、下载、存盘耗时，以及 CPU 内存和 GPU 峰值；
- 明确的完成状态。

保持 b 和 bdag 为两个独立坐标。只做块级续跑即可：已完成块经元数据验证可复用，失败块重跑。不必为本单建设复杂的任意步 checkpoint 系统；若采用时间分段，必须连续传递状态、绝对时刻/自由场相位及累计输出行，不能重新置初态或重复积分。

用新结果目录，排他写入或临时文件完成后发布；不能覆盖既有结果，也不能把未写完的文件当完成块。

merge 必须拒绝：
- 重复、遗漏或未知列；
- 两套 manifest/参数/步长/初态/探测定义混用；
- 暗列重复或缺失；
- 尚未完成、shape 不符或包含非有限数的块。

按全局列标签合并：
U = U0 + delta_U。
复用既有约定 n = V.conj() @ V.T、m = U @ V.T；
正常 CCR 为 U U† - V V†，反常为 U Vᵀ - V Uᵀ。
保留 U0 Vᵀ，不能用 delta_U Vᵀ 代替完整 m；不要对输出做事后归一来“修复”CCR。

部分列、部分时长的这些收缩只可用于检查实现是否等价。它们不是完整 n,m，更不能要求部分列重建单位 CCR。完整输入的 CCR 和物理误差资格留给真正全量结果。

## 5. C：小范围验证，通过后自动继续

C1. 用现有 256 列、16 步 fixture 跑新 prepare/worker/merge。
复用独立复核的整块结果作为参考；验证落盘后再读回、分块合并、U0 与输出收缩。采用既有逐元素 atol=1e-10、rtol=1e-8；这是后端一致性，不是物理收敛门槛。验证缺一块/重复一块/manifest 不同会被明确拒绝。

C2. 去掉“2T 重置初态”的限制，做一个真正连续的小列集。
- +N，ntpc=1024，t=0 到 2T+128 个时间步，共 2176 步。
- 使用完整冻结 P1 波形和原 H2 探测核，只截取积分时间；不要把包络压缩成两周期，也不要重归一探测核。
- 选取真实不同频率列，覆盖低频、H2、中频、高频和暗列。
- 以最多 1024 个真实列为同一集合，按 256/512/1024 块大小比较；不复制相同列伪装扩容。内存不足可先停在 512 并如实报告。
- 为避免重复，最大列集的 driven/undriven 各自连续推进到 2T 一次；后续吞吐测试可从对应实际状态的切片出发，跑相同 128 步。这里不是 stationary 重置。
- 选 32–64 个混合列做 CPU 参考，也从 t=0 连续推进到同一终点，与 GPU 对应全局 ID 核对 b、bdag、A、电流和两条路径/相减输出行。无需所有列重跑 CPU。

最终保存完整小列集累计结果，并核对新 runner 的分块/续接与不中断整块结果。遇到精度差先定位代码、相位、归一或累加问题，不放宽物理门槛去掩盖。

## 6. D：用实际执行路径重新记预算

上一轮 8.78–9.92 h 仅是旧短测算术外推，本轮不得直接沿用为核心循环预算。

原始 benchmark JSON 直接落盘，保留每次重复，不只保存最快值。预热与冷启动分开；GPU 计时同步。吞吐比较使用同一真实列集、同一时间段，分别测 driven 和 undriven，不能只测一条后乘二冒充实测。

按下式估计长任务：
一次共同准备 + 各块(装配/读取 + 上传 + driven 循环 + undriven 循环 + 下载/落盘) + 合并。

循环用驻留设备的持续步进测量；只对循环项按步数外推。每块启动/上传/下载只按实际调用次数计入。公共背景缓存一次；如果实现实际会重复上传共同顶点，也要按实际次数计入并说明。

可以准备完整 9216 步的公共电子顶点缓存，以取得真实准备时间；这不是全列量子传播。若本轮未做，则单独列为外推/未测，不能宣布完整预算已实测。

报告 256/512/1024 中合理的块大小，及单 GPU 顺序分块的基准账。先不做多 GPU、多进程 GPU 竞争或服务器并发优化；吞吐不足时再有依据地扩展。服务器迁移时核对实际硬件及调度，不沿用本机型号/显存判断。
