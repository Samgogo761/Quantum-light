## 四、服务器并行和合并契约

### 并行边界

按入射 photon column block 并行。每个 block 内必须保留：

- 全部 2304 个电子坐标；
- 同一个 block 的共同自洽反馈；
- 独立传播的 `b` 与 `bdag`；
- driven 和 undriven 两条路径，直到 reference 替代方案另行通过。

禁止把 k 分成互不反馈的 block。

### 暗列

- 1976 个 dark columns 只装配一次并缓存。
- dark columns 可以作为普通独立列分块传播；
- 不要为每个 photon block 重新生成整套 dark basis。
- 合并时保持 canonical column order：photon columns 按频率/偏振/端口原顺序，dark columns 置于约定的末尾位置。

### 输出

每个 block 至少保存：

- `column_start`, `column_stop`；
- `freq` 及其原始索引；
- `has_dark`、`n_point`；
- driven−undriven 的 `delta_u` 和 `v`；
- driven/undriven wall time；
- 后端、精度、输入哈希和版本标识。

合并前必须验证：

- block 覆盖无空洞、无重叠；
- photon 频率索引严格回到全局顺序；
- dark columns 恰好出现一次；
- 每个 block 的 `n_point` 与数组列数一致；
- `delta_u`、`v` 的 shape 与全局列数一致。

## 五、服务器对话先执行的顺序

1. 确认 GPU 型号、显存、driver、CUDA runtime、PyTorch 版本和调度分区。
2. 在服务器运行与本地相同的 16 步 mixed-frequency/H2/high/dark short fixture。
3. 测 block size 64/128/256，必要时再测 512/1024；报告总 wall、设备 loop、H2D/D2H、峰值显存。
4. 以目标 block size 跑一个非零泵浦窗口的单 block CPU/GPU 对照。
5. 测一次真实的 block 输出和 merge 校验；不启动 9216 步全列。
6. 根据实测吞吐、预处理/顶点缓存和写盘成本重新算 wall-time，确认资源授权。
7. 只有资源账和启动/合并脚本均通过，才讨论首条 Γ12 `+N` 八周期加尾试算。
