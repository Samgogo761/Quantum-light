# BSV 确定性强度求积:方案与执行（2026-06-12）

替代 MC 采样的生产方案。背景见 `BSV_pilot结果与生产策略_20260608.md`(51 样本 MC
的相对误差 18–44%,压到 10% 需 ~970 样本,不可行)。

## 1. 数学

BSV 随机相位平均 = 对指数强度分布的一维积分:
```text
HHG_bsv(ω) = ∫₀^∞ dx e^(-x) S(ω; I₀·x),   x = I/I₀,  I₀ = 2×10¹¹ W/cm²
```
用 **复合 Gauss-Legendre(8+8 节点,[0,6]∪[6,18])+ 显式 e^(-x) 权重**。
选它而非截断 Gauss-Laguerre:数学干净(截断误差显式 ~e^(-18))、低 x 区节点更密
(低次谐波质量集中在 x≈1–3)。

**已验证**(`deploy/bsv_quad_nodes.dat` 头部):16 节点复现指数矩 ⟨x^p⟩=p!:
```text
p=1..3: <2e-5    p=5: 3e-4    p=7: 3e-3(≈H13 的有效标度)    p=9: 1.5e-2
```
即:16 次确定性经典 run ⟹ ≤0.3% 求积误差(到 p_eff≈7),零 MC 噪声。
对比 MC:等效精度需 ≥10⁴ 样本。**便宜 >100×。**

## 2b. 编译环境坑(2026-06-13 修复)

array 任务全部"compile wait timeout"。**所有 sbatch 脚本的 LD_LIBRARY_PATH 必须以
`.../vtune/2023.2.0/lib64` 打头**(它提供 ifort 需要的新 libstdc++)。已修复,并把
"node 0 编译、其余等"的脆弱逻辑换成 **原子 mkdir 锁**(任意任务抢锁编译,与调度顺序无关,
`.compile_quad.done` 标记 + make clean 处理 Windows 残留)。

## 3. 执行(服务器,≤3 节点)

```bash
cd <仓库根目录>
sbatch deploy/run_bsv_quadrature.sh
#  TB 不在默认位置: TB_FILE=... sbatch deploy/run_bsv_quadrature.sh
# (强烈建议)最强节点的 dt 收敛检查,与主 array 并行提交:
DT_AU=0.175 OUTROOT_SUFFIX=_dt0175 sbatch --array=15 deploy/run_bsv_quadrature.sh
```
墙钟:16 run × ~1.9h ÷ 3 节点 ≈ **11–12 h**(dt-check 4h 并行其中)。

全部完成后(本地或 python3 节点):
```bash
python3 tools/analysis/combine_bsv_quadrature.py \
  --quad-root output_bsv_quad --nodes deploy/bsv_quad_nodes.dat \
  --classical <verify run 的 HHG.dat> \
  --mc <output_bsv/HHG_bsv_pooled.dat>
```

   若 z 大则暴露 CEP 依赖,需补 φ=0° 一套求积取平均)。
3. dt-check:node_15 在 dt=0.35 vs 0.175 的 H1-H13 变化 <~2% ⟹ 强场端时间步收敛。

物理读法:
```text

   平台谐波 I-标度远弱于 I^n,故增强饱和在 n! 之下。
3. 机制:指数强度分布的高强度尾延展 HHG cutoff,越靠近/越过经典 cutoff 的谐波

5. MC(51 样本)系统性偏高 ~1.5σ(抽到的高 I 样本偏多)=> 求积给出更低更可信的真值
   (如 H13:求积 363 vs MC 949)。
```
