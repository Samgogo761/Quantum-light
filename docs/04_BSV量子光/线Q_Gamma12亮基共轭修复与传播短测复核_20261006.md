## 4. 为何不开 \(+N\)，GPU / 服务器怎么接

本机与 Workbuddy 仍无 torch/cupy/numba。未装包、未新建 venv：没有可对照的 GPU 核，装包本身不能启动脉冲。

43 h 单线程 CPU 超出 3 h 门，也未授权长作业。`part_1` 36 核只能加速 2×2304 与 2304×ncol 的 gemm；时间步仍串行，粗估仍十几小时量级，且没有 CPU 多线程回归。RTX 5060 Ti 16 GB：状态 \(b,b^\dagger\) 约 6 GB，显存上放得下，但代码路径还不存在。

可执行下一工程（无需物理人审）：

1. 隔离 venv，按官方 CUDA 装双精度 torch；保留 pythoncore-3.14 CPU 基准。
2. 列块 `midpoint_step` 的 gemm 与 2×2 Schur 放到 GPU；顶点仍 CPU；每步共享 \(u(t)\)。
3. 先 16 步、256 列：状态 / 电流 / \(U,V\) 行与 CPU 对照。
4. 对照通过后再用实测 GPU 吞吐重估 78472×9216；低于可承担墙时才开首条 +N。
5. 服务器仅在本机 GPU 方案失败且有明确墙时配额时用 `part_1`，脚本须分频块、共享顶点。
