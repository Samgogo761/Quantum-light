# Zotero 文献导入与 AI 管理指南（2026-06-26）

## 0. 现在能做到什么

当前 Codex 里的 Zotero MCP 已经可以读取 Zotero：

- 搜索条目；
- 读取元数据；
- 读取全文或附件全文索引。

但它目前不能直接写入 Zotero，也就是不能通过现有 MCP 完成：

- 创建 collection；
- 移动条目；
- 导入 PDF；
- 修改 title、tags、notes；
- 添加附件。

Zotero 官方本地 API 位于 `http://localhost:23119/api/`，但截至 2026-06-26，官方文档说明本地 API 只支持 `GET`，不支持写入请求。真正可写的是 Zotero Web API，需要 Zotero 账号、同步库和有写权限的 API key。

因此最稳妥的路线是：

1. 先用本指南在 Zotero 中手动或半自动导入 PDF；
2. 我负责读取 `Downloads` 和 Zotero，生成“导入清单、分类建议、标签建议、中文标题翻译、重复检查”；
3. 如果之后确实需要全自动写入，再走 Zotero Web API key 路线。

参考：

- Zotero Local API: https://www.zotero.org/support/dev/web_api/v3/local_api
- Zotero Web API Write Requests: https://www.zotero.org/support/dev/web_api/v3/write_requests
- Zotero Web API File Uploads: https://www.zotero.org/support/dev/web_api/v3/file_upload

## 1. 先修正 Zotero 父分类不显示子分类文献的问题

在 Zotero 中打开：

```text
View -> Show Items from Subcollections
```

中文界面可能是：

```text
视图 -> 显示子分类中的条目
```

打开后，点击父分类“陆老师”时，应该会显示其子分类“博士课题”中的文献。这个设置会显著减少重复搜索。

## 2. 推荐 collection 结构

建议在 Zotero 中建立如下结构：

```text
陆老师
└── 博士课题_量子光CrI3
    ├── 00_研究主线_必读
    ├── 01_量子光驱动HHG
    ├── 02_SBE_规范_数值方法
    ├── 03_CrI3_磁性_非互易_HHG
    ├── 04_量子光统计_FCS_QRT
    ├── 05_非经典性_矩判据_QFI
    ├── 06_Berry_量子几何_磁群
    ├── 07_材料benchmark_hBN_ZnO
    ├── 90_待阅读_待归类
    └── 99_综述_教材_背景
```

原则：

- 一篇文献可以放入多个 collection，不需要只属于一个分类。
- `00_研究主线_必读` 只放真正会反复引用、影响课题叙事的核心文献。
- `90_待阅读_待归类` 用作临时入口，避免 Downloads 里的 PDF 直接散落进多个分类。

## 4. 中文标题翻译与检索说明怎么放

不要直接把 Zotero 的英文 `Title` 字段改成中文。英文标题是检索、引用和 DOI 匹配的核心字段，最好保持原样。

推荐做法：给每篇重要文献添加一个子笔记，格式如下：

```text
中文标题：
……

一句话定位：
……

和本课题的关系：
……

建议标签：
project:AFM-CrI3-BSV; topic:...; role:...
```

如果需要更轻量，也可以把中文标题放入 `Extra` 字段，但子笔记更适合后续让 AI 读取和总结。

## 5. 从 Downloads 导入 PDF 的手动流程

以 `C:\Users\26507\Downloads` 为例。

### 5.1 先建入口 collection

在 Zotero 中新建：

```text
陆老师/博士课题_量子光CrI3/90_待阅读_待归类
```

### 5.2 分批导入 PDF

不要一次拖入几百个 PDF。建议每次 10-30 篇：

1. 在 Zotero 中点击 `90_待阅读_待归类`；
2. 将 `Downloads` 中一批 PDF 拖入该 collection；
3. 选中新导入的 PDF；
4. 右键：

```text
Retrieve Metadata for PDF
```

中文可能是：

```text
从 PDF 获取元数据
```

Zotero 会尝试根据 DOI、arXiv、标题等自动创建父条目。

### 5.3 处理元数据失败的 PDF

如果 PDF 仍只是附件，没有父条目：

1. 打开 PDF 第一页，找到 DOI 或 arXiv ID；
2. 在 Zotero 中点击魔杖按钮：

```text
Add Item by Identifier
```

输入 DOI/arXiv ID；

3. Zotero 创建父条目后，把 PDF 拖到该条目下面，作为附件。

如果没有 DOI/arXiv：

1. 右键 PDF；
2. 选择 `Create Parent Item`；
3. 手动填 title、authors、year、journal。

## 6. 去重流程

导入一批后立刻去重，不要等全部导入完。

Zotero 左侧点击：

```text
Duplicate Items
```

逐个合并重复项。优先保留：

- 有 DOI 的条目；
- 有期刊信息的条目；
- 有 PDF 附件的条目；
- 有你自己笔记和标签的条目。

## 7. 分类流程

每篇文献建议按下面顺序处理：

1. 确认英文标题、作者、年份、DOI/arXiv；
2. 加入一个或多个 collection；
3. 添加 `project:*`、`topic:*`、`role:*`、`status:*` 标签；
4. 添加中文标题与一句话定位笔记；
5. 如果是核心文献，放入 `00_研究主线_必读`。

## 10. 如果要真正自动写入 Zotero

真正自动写入需要 Zotero Web API。

### 10.1 需要你准备

1. Zotero 已登录并同步到 zotero.org；
2. 到以下页面创建 API key：

```text
https://www.zotero.org/settings/keys
```

3. key 权限至少包括：

```text
Library access: personal library
Allow write access
```

如果要上传 PDF 到 Zotero 云端，还需要对应的 file access，并注意 Zotero 存储空间限制。

### 10.2 安全注意

不要直接把 API key 发在聊天正文里。更安全的方式是在本机设置环境变量：

```powershell
$env:ZOTERO_API_KEY="你的key"
$env:ZOTERO_USER_ID="你的userID"
```

或者写入一个不进 Git 的本地 `.env` 文件。

### 10.3 自动写入能做什么

通过 Zotero Web API，可以：

- 创建 collection；
- 创建/修改 item；
- 添加 tags；
- 添加 notes；
- 添加/上传 attachment；
- 将 item 放入指定 collection。

但这条路线会直接改你的 Zotero 云端库，建议先用 5-10 篇文献做小样本测试。

## 11. 不建议的路线

不建议直接修改 Zotero 的 SQLite 数据库。原因：

- 容易破坏 Zotero 数据库；
- 可能与同步状态冲突；
- Zotero 官方也不推荐外部程序直接写数据库。

也不建议一开始就用 GUI 自动化批量点 Zotero。GUI 自动化可以做，但对窗口焦点、语言界面、弹窗非常敏感，适合最后处理少量重复操作，不适合大规模导入。
