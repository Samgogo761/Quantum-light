# 经典光规范与带窗测试总结（2026-05-17）

本文总结截至 2026-05-17 的新 SBE 求解器经典光测试结果，重点是 `matrix_vg`、Peierls `vg`、带窗截断、k 网格和下一步长度规范测试的判断。本文用于与外部 AI 或后续线程讨论，不进入 BSV 生产计算。

## 1. 当前总原则

BSV 计算暂时冻结。原因是经典光路径中的规范选择、带窗截断和退相干参数语义尚未完全锁定。BSV 每个样本都要重复经典光传播，在经典光没有稳定前进入 BSV 会浪费大量计算资源。

当前优先级：

1. 先解决经典光规范与带窗问题。
2. 再做退相干参数的物理扫描。
3. 最后才进入 BSV 小样本可行性测试。

## 2. 已确认的退相干语义

旧求解器中输入 `deph_t2 = 0.5` 不是 0.5 fs，而是 0.5 个光周期。对于 3200 nm 驱动光：

```text
T_cycle ≈ 10.674 fs
旧 deph_t2 = 0.5 ≈ 5.337 fs
```

新求解器中：

```text

```

是真正的 0.5 fs。因此新旧输入文件表面同为 `0.5`，物理退相干强度相差约 10.7 倍。

本轮规范/带窗测试均采用：

```text

```

也就是近似关闭退相干，用于先检查代码路径和规范/截断本身。

需要谨慎解释的是，这个差异不能简单归因于“`matrix_vg` 只是一阶 A 近似”。代码中 `matrix_vg` 的速度算符为：

```fortran
vk_a = Pk_eq
vk_a(n,n) = vk_a(n,n) + A_now(a)
```

也就是包含显式 `+ A I` 项；而 Peierls `vg` 的速度算符是 `dH(k+A)/dk`。因此 H1 的巨大差异很可能同时包含：

- Hamiltonian 线性化误差；
- 电流/速度算符定义不在同一个规范实现中的差异；
- 有限 Wannier 窗口和截断空间中的 sum rule / gauge covariance 问题。

## 7. 当前物理解释

这更像 Peierls 速度规范下“对称带窗截断”破坏了填满价带的电流抵消，而不是普通代码错误。

代码逻辑：

```fortran
nv = nv_orig - nb_start + 1
```

随后初始密度矩阵只填充截断窗口内的 `1:nv`：

```fortran
do n = 1, nv
  rho(n, n, ikx, iky) = C_1
end do
```

因此对称带窗下保留的占据价带数为：

```text
20 bands: nb_start=75 -> 10 occupied valence bands
30 bands: nb_start=70 -> 15 occupied valence bands
40 bands: nb_start=65 -> 20 occupied valence bands
50 bands: nb_start=60 -> 25 occupied valence bands
60 bands: nb_start=53 -> 32 occupied valence bands
112 bands: nb_start=1  -> 84 occupied valence bands
```

速度规范电流中深层价带虽然不一定直接参与带隙附近跃迁，但会参与巨大的背景电流抵消。截断掉大量深价带后，低阶响应会留下伪信号。

因此目前不建议用 Peierls `vg` 的对称 20/30/40/50/60 带窗作为生产路径。

## 8. 对外部建议的修正

外部建议中正确的部分：

- 需要做 `matrix_vg` vs 代码内部 Peierls `vg`；
- `matrix_vg` 内存远小于 Peierls `vg`；
- BSV 前必须先解决经典光规范问题；
- `lg_cov` 不能只靠 `10x10` 判断，最终需要更密 k 网格。

需要修正或补充的部分：

- `matrix_vg` vs Peierls 不一致不能只解释为“少了 A 的二阶/高阶项”，因为当前 `matrix_vg` 电流算符还含 `+A I` 项。
- “全 112 带 matrix_vg 可行”不代表它就是生产路径，Phase 0 已经显示当前实现与 Peierls 差异很大。
- “深价带不参与物理过程，所以可以截掉”这句话在速度规范电流中不安全。深价带可能通过 sum rule / 背景电流抵消影响低阶谱。
- 对 Peierls `vg`，比“围绕带隙的对称带窗”更合理的测试是“保留全部价带 + 截断导带”，例如 `nb_start=1, nb_end=94/104/112`，但这种配置内存更重，20x20 以上更适合服务器。

## 11. Houston 规范/基底的当前判断

旧求解器确实有 Houston 分支：

```text
var_method = "ht"
```

对应旧代码：

```text
C:\Users\26507\Documents\量子光研究\script5\src\submod_sbes_ht.f90
```

旧 Houston 分支的核心形式更接近“在加速晶体动量 `k+A(t)` 的瞬时本征/Houston 基底中做长度规范传播”：

```fortran
Ht = H0_kt + E(t) * A_kt
drho_dt = -i[Ht, rho]
```

并且电流使用 `Pmn(k+A)`、`dE/dk(k+A)`、Berry curvature 和 connection-gradient 等量。它不是当前新求解器的 Peierls `vg` 截断实现，也不是 `matrix_vg` 的 `H0 + A·P` 线性速度规范。

因此，对“速度规范对称截断会产生价带背景虚电流”的结论，不能简单外推为“Houston 分支也一定同样坏”。Houston/长度规范类方法通常更适合 active-window 截断，因为：

1. 传播 Hamiltonian 主要由 `H0(k+A)` 或 `H0(k)` 加 `E·A/D` 构成，不依赖速度规范里巨大的 `A` 耦合矩阵截断抵消；
2. 对每条完整保留的能带，BZ 上 `∫BZ ∂k ε_n(k+A) dk` 由于周期性应接近零，低阶背景电流问题通常比 Peierls 对称截断轻；
3. 截断误差更多表现为虚跃迁完备性、Berry connection、有限差分/插值和高阶谱收敛问题，而不是 H1/H3 三四个数量级的价带背景虚电流。

但 Houston 也不是自动安全：

- 如果 active window 太小，跃迁通道和 Berry connection 的 sum rule 仍会被破坏；
- `k+A(t)` 大幅移动时，对插值、相位连续性和能带排序很敏感；
- 旧 Houston 数据可以作为重要对照，但不能直接替代新求解器中的 `lg_cov` 验证。

当前新求解器里：

```text
gauge_method = 'houston_lg'
```

目前只是 `lg_cov` 的别名，会进入 `propagate_lg_covariant()`，不是旧求解器那套真正的 `submod_sbes_ht.f90` Houston 实现。

结论：旧 Houston 结果值得作为“长度规范/Houston 类 active-window 是否靠谱”的历史参考；但当前新求解器的生产候选仍应先验证 `lg_cov`，再决定是否需要移植/复现旧 Houston 分支。

### 22.4 旧长度规范与新 lg_cov 是否一致

旧求解器 `lg` 与新 `lg_cov` 的方程结构相似：

```text
H = H0 + E·A/D
rho_dot 包含 E·∂k rho
current 使用 P·rho
```

但二者不是逐行等价实现：

```text
旧 lg:
  使用旧代码中的 Amn、Pmn、grad_rho、gen_grad_Amn 等实现；
  有旧代码的电流分解、输出步长和退相干逻辑。

新 lg_cov:
  使用 Wannier tb.dat 中的 rmn_R 构造 Dk_eq 和 Pk_eq；
  用平行输运的协变有限差分计算 D_k rho；
  RK4 同步推进全 k 网格；
  退相干使用新代码的瞬时本征基处理。
```

因此只能说“物理形式接近”，不能说“计算逻辑完全一致”。若要比较旧 LG 与新 LG，需要单独跑旧 `var_method="lg"` 同条件结果。

### 22.5 为什么新速度规范比旧求解器快

速度差不代表物理逻辑一定一致。可能原因包括：

```text
1. 新代码预计算矩阵并使用更直接的数组布局；
2. 新代码输出诊断更少，旧代码会频繁写 rho、Jt、分解电流等文件；
3. 新旧编译器、OpenMP、MKL 设置不同；
4. 新 Peierls vg、新 matrix_vg、旧 vg 本来就不是同一条算法路径；
5. 新 matrix_vg 内存和计算结构比 Peierls HR_proj 路径轻得多。
```

因此速度更快不能作为“实现完全一致”的证据，也不能单独说明“有 bug”。应以同条件谱、电流和规范交叉验证为准。
